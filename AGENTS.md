# go-label-studio

Unofficial Go client for the Label Studio API, generated from HumanSignal's public OpenAPI document. If you only want to use the client from an agent, read [.agents/skills/go-label-studio/SKILL.md](.agents/skills/go-label-studio/SKILL.md) instead; this file is about changing the code.

## Architecture

One generated package, `labelstudio`, at the module root, driven by `gen.go`:

`scripts/fetch-spec.sh` downloads `https://raw.githubusercontent.com/HumanSignal/label-studio-client-generator/master/fern/openapi/openapi.yaml` to `api/openapi.yaml`, then oapi-codegen with `config.yaml` writes temporary `client.gen.go`; `scripts/split-gen.sh` splits it at declaration boundaries into `client_*.gen.go` files.

## Stack

- Go 1.26.9.
- oapi-codegen, pinned as a `tool` dependency in `go.mod`.
- Runtime: `github.com/oapi-codegen/runtime`.

## Layout

- `gen.go`, `config.yaml`, `client_*.gen.go`: the package.
- `client_test.go`, `example_test.go`: tests, including the README example.
- `scripts/`: spec download, generated output splitting, lint and security scan scripts.
- `api/`: the downloaded spec, gitignored.
- `vendor/`: committed, regenerated by `make dep`.

## Dev workflow

Everything runs in the `Dockerfile.dev` image. You need Docker and Make.

```bash
make dep       # go mod tidy + go mod vendor
make generate  # download the spec and regenerate
make lint      # shellcheck, shfmt, go fix, golangci-lint
make test      # go test -race
make sec       # gitleaks, govulncheck, semgrep
```

## Project-specific landmines

- The provider document declares OpenAPI 3.0.3 but leaves `info.version` empty. Do not invent an API version.
- The source repository uses `master`, not `main`.
- User-supplied base URLs point at the server origin. Operations already include `/api/`.
- The `Token` scheme sends `Authorization: Token <token>`. Supply it through `WithRequestEditorFn`; generated clients do not add credentials automatically.
- The whole spec includes Enterprise operations. A generated method does not imply that every server edition supports its endpoint.
- The whole spec generates directly without schema patches. The split step changes file layout only and must preserve every declaration.
- Keep `resolve-type-name-collisions` and `always-prefix-enum-values` in `config.yaml` to avoid duplicate Go declarations across the full spec.
- Keep the `number` to `float64` mapping in `config.yaml`.
- Method names follow operation IDs. Check the generated signatures before writing examples.
- `make generate` always downloads the current spec, so it can change the client even when nothing here changed. Review the generated diff before committing it.
- `.github/workflows/regen.yml` regenerates the client every day and releases the result. When checks fail, Claude edits the repository, but a fix may not touch the paths listed under `fix_protected_paths`: workflows, Makefile, `AGENTS.md`, `.agents/rules/`, lint, security and spec download scripts and their configs. A problem there needs a manual fix.
